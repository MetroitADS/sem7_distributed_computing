## 2. Разбор Задания 1: Сумма ряда (массива данных)

### 2.1. Алгоритмическая логика и структуры данных

При суммировании огромного массива ($10^8$ элементов типа `int32_t`) ключевыми факторами производительности являются:
1. **Декомпозиция диапазона данных**: непрерывный массив делится на $T$ непересекающихся смежных отрезков $[\text{start}_t, \text{end}_t)$. Каждый поток обрабатывает исключительно свой участок памяти, что максимизирует последовательное чтение из оперативной памяти (Hardware Prefetching).
2. **Предотвращение False Sharing (ложного разделения кэш-линий)**: если разные потоки записывают промежуточные результаты в соседние элементы общего массива, ядра процессора постоянно сбрасывают L1/L2 кэш-линии друг друга (Cache Line Bouncing). Чтобы этого избежать, каждый поток пишет в структуру `PaddedSlot`, выровненную по границе кэш-линии (64 байта):
   ```cpp
   struct alignas(64) PaddedSlot {
       int32_t value = 0;
   };
   ```
3. **SIMD-векторизация (AVX2)**: в 256-битный векторный регистр `__m256i` помещается ровно 8 чисел `int32_t`. С помощью инструкции `_mm256_add_epi32` процессор выполняет сложение 8 пар чисел за один такт. Для максимальной загрузки конвейера процессора применен развертывание цикла (Loop Unrolling x4): используются 4 независимых векторных аккумулятора (`vsum0`, `vsum1`, `vsum2`, `vsum3`), что позволяет за одну итерацию обрабатывать 32 элемента (128 байт данных).

### 2.2. Пошаговый разбор ключевых фрагментов кода

#### 1. Однопоточная функция (`sum_single_thread`):
```cpp
int32_t sum_single_thread(const int32_t* data, size_t count) {
    int32_t total = 0;
    for (size_t i = 0; i < count; ++i) {
        total += data[i];
    }
    return total;
}
```
* **Назначение:** Скалярное накопление суммы в регистре `total`. Служит эталоном (Ground Truth) и базовой точкой отсчета для измерения ускорения.

#### 2. Многопоточный воркер (`worker_sum_scalar`) и координатор (`sum_multi_thread`):
```cpp
void worker_sum_scalar(const int32_t* data, size_t start, size_t end, int32_t* result_slot) {
    int32_t local_sum = 0;
    for (size_t i = start; i < end; ++i) {
        local_sum += data[i];
    }
    *result_slot = local_sum;
}
```
* **Логика:** Накапливает сумму внутри локальной переменной `local_sum` (находящейся в регистре процессора или на стеке потока). Лишь после завершения цикла результат однократно сохраняется в персональный выровненный слот `result_slot`.
* **Запуск потоков:**
```cpp
size_t chunk_size = count / num_threads;
for (unsigned int t = 0; t < num_threads; ++t) {
    size_t start = t * chunk_size;
    size_t end = (t == num_threads - 1) ? count : start + chunk_size;
    threads.emplace_back(worker_sum_scalar, data, start, end, &partial_sums[t].value);
}
for (auto& th : threads) th.join();
```
* Потоки стартуют параллельно и синхронизируются через метод `.join()`. Главный поток суммирует $T$ частных сумм.

#### 3. AVX2 SIMD-векторизация (`sum_simd_avx2_block`):
```cpp
// Обработка блоков по 32 элемента
for (; i + 32 <= count; i += 32) {
    __m256i v0 = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(ptr + i));
    __m256i v1 = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(ptr + i + 8));
    __m256i v2 = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(ptr + i + 16));
    __m256i v3 = _mm256_loadu_si256(reinterpret_cast<const __m256i*>(ptr + i + 24));

    vsum0 = _mm256_add_epi32(vsum0, v0);
    vsum1 = _mm256_add_epi32(vsum1, v1);
    vsum2 = _mm256_add_epi32(vsum2, v2);
    vsum3 = _mm256_add_epi32(vsum3, v3);
}
```
* **`_mm256_loadu_si256`**: Загрузка 256 бит данных из невыровненной памяти в векторный регистр.
* **`_mm256_add_epi32`**: Параллельное 32-битное сложение 8 упакованных целых чисел со знаком.
* **Сведение аккумуляторов и горизонтальная редукция:**
```cpp
vsum0 = _mm256_add_epi32(vsum0, vsum1);
vsum2 = _mm256_add_epi32(vsum2, vsum3);
vsum0 = _mm256_add_epi32(vsum0, vsum2);

alignas(32) int32_t buffer[8];
_mm256_storeu_si256(reinterpret_cast<__m256i*>(buffer), vsum0);
int32_t local_sum = 0;
for (int k = 0; k < 8; ++k) local_sum += buffer[k];
```
В конце вектор из 8 чисел выгружается в массив и складывается в одно скалярное значение, после чего обрабатывается остаток элементов, если размер не кратен 32.

## 3. Разбор Задания 2: Умножение матриц 4096 x 4096

### 3.1. Анализ вычислительной сложности и архитектурные оптимизации

Умножение двух квадратных матриц $A_{N \times N}$ и $B_{N \times N}$:
$$C[i][j] = \sum_{k=0}^{N-1} A[i][k] \cdot B[k][j]$$
* **Общее число скалярных умножений и сложений:** $N^3 = 4096^3 = 68\,719\,476\,736 \approx 68.7$ миллиарда операций!
* **Проблема наивного алгоритма:** обращение к $B[k][j]$ происходит с шагом $N$ (4096 элементов $\times$ 4 байта = 16 КБ). Каждая итерация внутреннего цикла по $k$ приводит к промаху мимо кэша процессора L1/L2 (Cache Miss), снижая утилизацию ядер процессора до единиц процентов.
* **Решение (Кэш-ориентированное транспонирование):** предварительно транспонируем матрицу $B$ в матрицу $B^T$:
  $$B^T[j][k] = B[k][j]$$
  Тогда скалярное произведение $i$-й строки $A$ и $j$-го столбца $B$ превращается в скалярное произведение двух **непрерывных строк в оперативной памяти**:
  $$C[i][j] = \sum_{k=0}^{N-1} A[i \cdot N + k] \cdot B^T[j \cdot N + k]$$
  Процессор читает смежные адреса памяти подряд, данные автоматически загружаются в L1-кэш линиями по 64 байта, а аппаратный префетчер упреждающе доставляет следующие строки. Это снижает время выполнения более чем в 10 раз!

### 3.2. Логика параллелизации с `std::thread`

Матрица результата $C$ содержит 4096 строк. Мы разбиваем диапазон строк $i \in [0, 4096)$ между 16 потоками:
* Поток 0: строки $[0, 256)$
* Поток 1: строки $[256, 512)$
* ...
* Поток 15: строки $[3840, 4096)$

Каждый поток пишет исключительно в свой диапазон строк матрицы $C$. Потоки читают общие матрицы $A$ и $B^T$ (только чтение, Data Sharing без модификации), что гарантирует полное отсутствие гонок данных (Data Races) и не требует использования блокировок или мьютексов.

```cpp
void worker_multiply_rows(const int32_t* A, const int32_t* BT, int32_t* C, int n, int start_row, int end_row) {
    for (int i = start_row; i < end_row; ++i) {
        const int32_t* a_row = &A[i * n];
        int32_t* c_row = &C[i * n];
        for (int j = 0; j < n; ++j) {
            const int32_t* bt_row = &BT[j * n];
            int32_t sum = 0;
            for (int k = 0; k < n; ++k) {
                sum += a_row[k] * bt_row[k];
            }
            c_row[j] = sum;
        }
    }
}
```

## 5. Выводы

1. **Анализ Задания 1 (Эффект бутылочного горлышка памяти — Roofline Model):**
   - Переход от одного потока к 16 потокам дал ускорение **4.75x** (сокращение времени с 32.18 мс до 6.78 мс).
   - Добавление AVX2 SIMD-инструкций к 16 потокам дало практически аналогичный результат (6.76 мс, ускорение **4.76x**).
   - **Причина:** Операция редукции массива относится к категории **Memory-Bound** (ограничена пропускной способностью шины памяти). Размер массива составляет ~381 МБ. Чтение 381 МБ за 6.76 мс соответствует реальной пропускной способности оперативной памяти:
     $$\text{Bandwidth} = \frac{381.47 \text{ МБ}}{0.00676 \text{ с}} \approx 56.4 \text{ ГБ/с}$$
     Это значение предельно близко к физическому максимуму пропускной способности двухканальной оперативной памяти DDR5. Вычислительные ядра и SIMD-векторы простаивают в ожидании данных из контроллера памяти, поэтому дополнительное ускорение за счет AVX2 при суммировании памяти не проявляется.

2. **Анализ Задания 2 (Вычислительно-емкая задача — Compute-Bound):**
   - Умножение матриц требует выполнения $68.7$ млрд арифметических операций. Благодаря транспонированию матрицы $B$, операции с памятью локализованы в быстрых L1/L2/L3 кэшах.
   - Задача является **Compute-Bound** (ограничена производительностью АЛУ процессора).
   - Многопоточная реализация `std::thread` на 16 потоках показала ускорение **9.10x** (время сократилось с 5.91 с до 0.65 с).
   - Ускорение 9.10x превышает количество физических ядер (8) благодаря технологии Simultaneous Multithreading (SMT), позволяющей утилизировать свободные вычислительные порты ядер процессора.
